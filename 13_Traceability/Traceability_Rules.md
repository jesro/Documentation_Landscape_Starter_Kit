# Traceability Rules

## Required links

### Requirement -> Decision

When a requirement materially drives an architectural decision.

### Decision -> Design

When the decision changes system structure or implementation constraints.

### Decision -> Evidence

When research, PoC or benchmarks materially support the decision.

### Design -> Implementation

When the design is specific enough to map to code/modules.

### Requirement -> Test

When a requirement must be verified.

### Change -> New Decision

When an architectural commitment changes.

## Principle

Traceability should answer:

> What requirement led to this decision, what evidence supported it, how was it implemented,
> and what test verifies it?

Do not create links merely to make the matrix look complete.
