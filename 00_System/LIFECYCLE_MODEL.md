# Documentation Lifespan and Lifecycle Model

## Four lifespan classes

| Lifespan | Examples | Treatment |
|---|---|---|
| Ephemeral | Raw conversation, brainstorm, scratch notes | May be discarded after useful knowledge is extracted |
| Temporary / evidence-producing | Spike, PoC, benchmark, feasibility study | Preserve while useful; findings should feed durable artifacts |
| Long-lived / current | Architecture, requirements, design, active ADR, API contract | Keep accurate and maintained |
| Historical | Superseded ADR, old architecture, incident, changelog | Preserve because it explains evolution |

## Rule of thumb

**Current documentation describes what is true now.**

**Decision documentation explains why it became true.**

**Historical documentation explains what used to be true and how it changed.**
